# Project: IL-TOD (ИЛ ТОД) - Open-Source Anti-Spin & Government Transparency News Platform (Mongolia)

@AGENTS.md

## 1. Mission & Core Philosophy
We are building a 100% transparent, open-source investigative news and public data monitoring platform for Mongolia, designed for **young readers** (fast, visual, mobile-first).
- **Anti-Brainwash Principle:** Separate hard verifiable facts (numbers, dates, laws, tender amounts, entities) from political PR spin.
- **Zero-Cost Infrastructure:** Must run strictly within free tiers (Vercel Hobby, Supabase Free 500MB PostgreSQL + pgvector, GitHub Actions for cron scraping on a public repo).
- **Dual-LLM Intelligence:** a bulk tier for extraction/summarization and a deep tier for high-risk items. Free tiers go first (Groq, NVIDIA NIM, Requesty's free Gemma, taking turns; Google Gemini free with a no-billing key, otherwise its cheapest model inside the USD budget); paid DeepSeek / xAI Grok are optional and capped by a USD budget; local Ollama is the last fallback.

### Scraper architecture (`src/lib/scraper`)
- `adapters/index.ts`: sources with a public API or feed skip HTML crawling: opendata.gov.mn, parliament.mn, zasag.mn (= `mongolia.gov.mn/feed` RSS with full HTML; zasag.mn's own cert and /news are broken, links are rewritten to mongolia.gov.mn) and legalinfo.mn (new legal acts via `POST /mn/ajaxLlist/`, text from the detail page's `.maincontenter`; `ScrapedItem.loadText` fetches details only for unseen URLs) and police.gov.mn (`/a/?page=1&size=20` cards → `/a/{id}`; the list has only the image-path day, `loadText` returns the text plus the exact time; image-only posts have no text and are skipped).
- tender.gov.mn and shilendans.gov.mn are `is_active = false` (Cloudflare 403 / no news). Do not try to get around Cloudflare; shilendans' JSON API (`back.shilendans.gov.mn/proxy/`) is a future budget-data source, not news.
- `--days <n>` backfill: WordPress REST `after=`, feed dates, and only items with a known publication date inside the window (undated items would be stored as "today").
- Titles (`titles.ts`): `chooseTitle` takes the first non-generic of Readability → `og:title` → first `<h1>` → `<title>`; `isGenericTitle` rejects section words ("Мэдээ", "Нүүр хуудас"), the site's own name or abbreviation ("Мэдээ | ТТХГ") and < 8 characters; the fallback is `firstSentenceTitle` (skips date lines). `unshoutTitle` (db-sink and the demo seed) turns ALL-CAPS headlines into sentence case, keeping abbreviations (`ACRONYMS`), initials ("Х.Баттулга") and common proper nouns. `db-sink` also treats a title this source already used in the last 30 days as the site's title (opendata excluded); a site title over glued menu text (`looksLikeNavigation`) is a homepage/menu page and is stored with `is_published=false`.
- Dates: `extractPublishedDate` checks meta tags, JSON-LD, the page's data blob (`jsonBlobDate`: `__NEXT_DATA__` / `__NUXT__` / `application/json` scripts with a `createdDate`/`date`/`publishedAt` key; mofa.gov.mn prints no date in its markup), `<time>`, the URL, then the headline area (date-ish class or a calendar icon between the headline and the body start, so "related news" dates below are ignored; anchored on the `<h1>` or the element holding the headline), then the text. Times are Ulaanbaatar (UTC+8). Undated items keep `published_at` = found time (feeds sort by it) but get `scrape_meta.date_unknown` ("Огноо тодорхойгүй" on the page, left out of the Google News sitemap), and an undated text whose newest year is before last year (`looksOld`) is stored unpublished. `npm run db:fix-titles` (`--dry-run`, `--dates`) repaired the rows stored before this.
- `src/lib/opendata-mn`: opendata.mn datasets via the portal's documented API (`/apiv1/file/{id}`, the URL its "API харах" button gives out). Its robots.txt disallows `/apiv1/` for crawlers; we skip the robots check for these documented API URLs only, keep the 8 s host delay, and sync at most twice a day. Only metadata and small computed highlights are stored (`open_datasets`), never raw rows.
- Source re-check (`recheck.ts`, `npm run sources:recheck`, weekly `source-recheck.yml`; a manual run is a dry run unless `dry_run=false`): the last 30 days of articles are fetched again with the same text getter (extractArticleSafe / police / legalinfo; opendata, parliament and zasag are skipped, as are admin-edited and pruned rows). Never compare hashes (widgets change). Lines we add when storing (legalinfo's "Батлагдсан байгууллага:") are skipped (`OUR_PREFIX`). `compareTexts` counts our stored sentences still on the page: below `CHANGED_BELOW` (0.8) or a changed number → `source_status='changed'` + `source_diff` (≤ 12 before/after or removed sentences); 404/410 or a redirect away on `GONE_CHECKS` (2) checks ≥ 6 days apart → `gone`; errors and failed extraction are skipped. The article page shows `SourceChangeNotice`, `/changes` lists them, and `/method#recheck` explains it. Wording stays neutral (a change can be a correction).
- `crawl.ts`: one Crawlee run for all other sources. Pass 1 = HTTP (WordPress REST API → RSS → link harvesting, homepage fallback). Pass 2 = headless Chromium (Playwright) only for sources whose news needs JavaScript.
  - WordPress: the REST base comes from `<link rel="https://api.w.org/">` (`wordPressApiBase`, handles `?rest_route=`); posts without `link` are reached as `/?p=<id>`; when the REST call fails or is empty the feed is tried, then the harvested links. Links (`links.ts`): an article id in the query string (`/?p=123`, `mn.php?page=40&news=1633`, `QUERY_ID`) counts, bare pagination (`?page=2`) does not; `[href]` on any element is harvested; `sameSite` never treats the parent domain (`gov.mn`) as the same site. A listing with < 3 article links is a splash page: `harvestSectionLinks` follows up to 3 news sections (`/home`, `/j`, `/c/medee…`, anchors reading "Мэдээ") one hop, once per pass (`pendingSections`). 404/410/451 pages are errors, and a listing reached with nothing stored and nothing known is a failure ("listing reached but no articles were stored"), so backoff works.
  - Dates: `parseDateValue` reads meta/JSON-LD/`<time>` values; no zone = Ulaanbaatar (+08:00). A `<time>` > 1 year older than the newest one on the page is a stray stamp (judcouncil.mn's 2019); a date printed in the text is only trusted when < 1 year old (mrpam's 2009 resolutions). "11-р сар" is November (`MONTH_LABEL`, lookbehind). `normalizeText` also strips the invisible Hangul/Braille fillers (U+3164 …) editors paste as a blank first line.
  - db-sink: `publishDecision` (`dates.ts`): dated items older than `MAX_AGE_DAYS` (60; a `--days` backfill widens it) are stored `is_published=false`; an undated text that names no year at all or whose newest year is before last year (`isTimelessPage`: department pages, instructions, a 2020–2024 programme) is stored unpublished too, and `NON_ARTICLE` skips `/p/<id>`, `/home`, `/posts`, `/instructions`, `page.aspx` paths (the section hop had pulled such pages onto the home page as "today's" undated stories); undated stories never become the lead card; a day-level date 30+ days old that this source already gave 10+ articles becomes `date_unknown` (stray stamp) instead. `npm run db:repair-dates` (`--dry-run`) applied these rules to the old rows and deactivated constcourt.mn (→ `conscourt.gov.mn`), inspection, dundgovi, orkhon, naog with the reason in `last_error`.
- Sources rotate least-recently-scraped first under a time budget; failing sources back off 2^n hours (`consecutive_failures`).
- `robots.ts` + `http.ts`: our own robots parser and 8s-per-host throttle for non-Crawlee fetches. The crawler uses the same `getRobots()` (not Crawlee's `respectRobotsTxtFile`, which treated an unreachable robots.txt as "allowed", refetched it before every request and ignored Crawl-delay): every queued request passes it (`add` in `runPass`), a refused listing fails like a failed request (`onFailure`, so home/feed fallbacks still apply), RFC 9309: 5xx or unreachable robots.txt = crawl nothing this run (`unavailable` says why in `last_error`). robots.txt is fetched with the page crawl's TLS stance (`robotsFetch`, got-scraping) so a broken .gov.mn certificate is not "unreachable"; the largest Crawl-delay (≤ 20 s) becomes the per-domain delay.
- Source health (`sourceError` in crawl.ts): a source whose every article request failed (403, timeouts) is failing, not healthy; sources the browser pass never reached because the HTTP pass used the budget stay uncompleted (first in line next run, no backoff). Dates in the future (`isFutureDate`: a timed one > 1 h ahead, a day-level one after today in Ulaanbaatar) are dropped in the extractor and again in db-sink (feeds/APIs). `stripHeavyTags` is a linear scanner (a self-closing `<svg/>` used to swallow the article up to the next `</svg>`). `/posts/<id>` links are articles; only the bare `/posts` listing is not. "Site | Headline" titles keep the headline (with two parts the longer one).
- `net-setup.ts` (imported by `http.ts` and `crawl.ts`) raises Node's per-address connect attempt from 250 ms to 3 s: from GitHub's US runners .gov.mn is ~250-300 ms away and 57 sources failed at once with an empty `AggregateError [ETIMEDOUT]`. `errorMessage()` reports the error code when the message is empty.

### AI pipeline (`src/lib/ai`)
- `router.ts`: provider chains. tier1 = Groq → Gemini → NVIDIA → Requesty → DeepSeek → Ollama; tier2 = Grok → Gemini → Groq → NVIDIA → Requesty → DeepSeek → Ollama (override with `AI_TIER1_CHAIN` / `AI_TIER2_CHAIN`). Tier-1 calls rotate the leading free providers (`spreadFree`: Groq, NVIDIA NIM, Requesty take turns; `AI_CONCURRENCY` 3), because a fixed order sent everything to Groq and left NVIDIA's free quota unused. Gemini: a key from a Google project WITHOUT billing (`GEMINI_FREE_TIER=true`) is free and keeps its place and the "-latest" models. A billed key (Oct 2026: the owner's "Paid 1" project was charged while the logs said $0) moves behind the free providers (`placeGemini`), uses only the cheapest text model `gemini-2.5-flash-lite` ($0.10/$0.40 per 1M, `GEMINI_BILLED_MODEL`; `geminiModel()` ignores a `GEMINI_MODEL`/`GEMINI_DEEP_MODEL` override that is not Flash-Lite), is priced per model (`geminiModelPrice`) and counts against the USD budget. Image, video and speech models are refused (`isTextModel`): the site never generates images. JSON mode + zod validation + one repair retry; one retry after a 429 (each retry passes the budget guard again). The OpenAI client runs with `maxRetries: 0`: the router owns retries (the SDK's default of 2 tripled 429s and timeouts). The repair attempt doubles `maxTokens` (cut-off JSON is the usual invalid reply). `ai:process` parks an article (`ai_error`) when `shouldPark(attempts)` (`fallback.ts`): two unusable replies, or every provider that answered gave one; outages alone never park. Only published rows are analysed or clustered (`is_published=false` rows, kept for dedupe, cost 44 % of the calls before Oct 2026). Articles that got the extractive fallback are offered to the AI again (`RETRY_FALLBACK_PER_RUN` 10 per run, newest first, `RETRY_FALLBACK_DAYS` 3); `processArticle` clears `summary_fallback`. Every call (success or failure with tokens) is logged with its USD cost via `usage-log.ts`; a provider-reported cost (Requesty) wins over the price table.
- `limits.ts`: budget guard checked before every call. Paid providers (price > 0, and Requesty always) stop at `AI_MONTHLY_BUDGET_USD` ($3) / `AI_DAILY_BUDGET_USD` ($0.30); every provider has `<PROVIDER>_DAILY_MAX_CALLS` (Grok 5) and optional `<PROVIDER>_RPM` throttling. Free providers keep working when money runs out. Never call a provider without passing a guard in production code (`dbBudgetGuard(db)`).
- Token budget: Tier-1 input is cut to 4,000 chars, Tier-2 to 8,000; opendata.gov.mn datasets are summarized by rules (`ruleBasedAnalysis`, 0 tokens).
- `analyze.ts`: `analyzeArticle` (pure, used by admin), `processArticle` (writes DB), `assignCluster`/`refreshCluster`.
- `risk_flag` is derived from `risk_score >= 65`, never trusted from the model. Regex MNT amounts are merged into entities.
- Clustering: stem Jaccard + entity overlap, threshold 0.45, cross-source only, 7-day window, published rows only; synthesis only at growth milestones. A same-headline channel (`SAME_HEADLINE` 0.8 title-stem Jaccard, ≥ 3 stems, and ≥ 0.3 body overlap) joins two sites posting one story with differently worded AI summaries while identical generic headlines about different events stay apart (`tests/fixtures/cluster-pairs.json`, real Oct 2026 pairs). `ai:process` clusters a whole run at once (`assignClusters`: one pool load, every row of the 7 days): the old per-article pool was capped at the 500 newest rows (~2 days) and found 3 clusters in a week. `npm run ai:process -- --recluster` reclusters the last 7 days; run it from the manual `maintenance.yml` workflow (also `refetch-dates`: `npm run db:repair-dates -- --refetch` re-dates the last 14 days' undated rows with the current extractor).
- Tier 1 also returns `importance_score` (0-100, national significance; optional, null when missing) and `topic` (one of `AI_TOPIC_KEYS`, unknown → null). `npm run ai:topics` tags older articles 25 headlines per call (runs after ai:process in the pipeline, a no-op when all are tagged); fallback rows are skipped and a row the model answered for twice without a usable topic (`scrape_meta.topic_attempts`, `TOPIC_MAX_ATTEMPTS`) keeps its domain topic.
- The article page names the model that really wrote each block (latest successful `tier1` / `tier2` call in `ai_usage_logs`, `aiModelLabel()`); never hardcode a provider name in reader-facing copy.
- `digest.ts`: "Онцлох тойм". `finalItems` enforces `MIN_DIGEST_STORIES` on the editor model's *final* list (invented ids dropped): fewer → the rule-based ranking writes the edition. Stories are excluded from the next editions by article id and by cluster (`clustersOf`). Articles are pre-ranked without AI (`rankScore`: importance, risk, cross-source coverage, source weight), one per cluster, top 40 (70 for "30d") go to the editor model (tier2 chain minus Grok), which picks 10 (20) and writes headlines + "why it matters". Model-invented ids are dropped; with no AI it falls back to the rule-based ranking. "12h" editions skip if one exists < 6 h old and do not repeat stories from the last 3 editions. A 12h edition needs `MIN_DIGEST_STORIES` (5): with fewer it widens to 24 h, then skips (no 1-story edition, no push). Scheduled editions come from the pipeline step `npm run digest -- --due` (`isDigestDue`: Ulaanbaatar 06–11 or 17–23 and ≥ 8 h after the last one), because GitHub starts `news-digest.yml` ~4.5 h late. The home strip labels an edition by its real time ("ОРОЙН ТОЙМ · 21:40"). The rule-based title names the top story.

## 4. Strict Scraping & Engineering Rules
1. Always check `robots.txt` and enforce a minimum 8-10 second delay between requests to the same `.gov.mn` domain.
2. Compute a `SHA-256` hash of cleaned article text before calling any LLM. Never process duplicate content.
3. Never store raw full-page HTML in Supabase (to protect the 500MB free limit). Store only cleaned text and structured JSON metadata.
4. Track every LLM API call's token usage and estimated USD cost in the `ai_usage_logs` table so the public `/transparency` dashboard is 100% mathematically accurate and live.
5. UI Language: All public UI labels, AI summaries, and analyses MUST be in clean, natural Mongolian (Cyrillic).
6. The site must build and render with **no** `DATABASE_URL` (empty states), so CI and contributors can run `npm run build` without secrets.

## 8. Admin & automation

Keep our own image links canonical (slugs are `[a-z0-9-]`; `encodeURIComponent` matches URLSearchParams for them).
- `subscribePush` is public: 10 per IP per hour (per instance), `PUSH_NEW_PER_HOUR` (500) new rows per hour and `PUSH_MAX_SUBSCRIPTIONS` (50k) in total, so nobody can fill the free database.
- Editing article text sets `edited_at` and the public page says so; `content_hash` keeps proving the original scrape.
- `.github/workflows/autonomous-news-pipeline.yml` (every 2h at :17, off the congested minute 0): migrate → scrape (HTTP + Chromium) → AI → push → due digest + its push. Every step after the scrape runs `if: !cancelled() && steps.migrate.outcome == 'success'`: a scrape or AI failure never skips the digest, its rule-based fallback or the pushes. `news-digest.yml` (08:07 / 20:07 Ulaanbaatar): opendata.mn sync + 12h digest; manual run with `kind=30d` for a monthly review. `discover-sources.yml` (weekly). The pipeline's manual run takes `days` for a backfill. `ci.yml`: check + build without secrets. Workflow inputs reach shell scripts only through `env:`. Secrets never reach `npm ci` / `playwright install` (dependency install scripts): job-level secrets are blanked on those steps, or set only on the steps that use them; keep it that way for new workflows and secrets.

## 8b. Autopilot (runs for months with nobody touching it)
- `keepalive.yml` (monthly): re-enables every scheduled workflow through the API; GitHub otherwise disables schedules after 60 days without repository activity. Add new scheduled workflows to its list.
- `npm run db:prune` (daily in news-digest): bodies of articles older than `RETENTION_DAYS` (180) are cut to a 600-character excerpt (`content_pruned_at`); title, AI summary, facts, link and the original SHA-256 stay, and the article page says so. Keeps the free 500 MB database at roughly one retention window (~6 KB per article). It also stores headlines still in capitals in sentence case (`unshoutTitle`; slugs stay).
- AI fallback (`src/lib/ai/fallback.ts`, start of `ai:process`): articles still unsummarized after 24 h, or parked with `ai_error`, get their first sentences as the summary (`summary_fallback`, importance 30, page label "AI ажиллаагүй", no fact/spin panel), so news keeps appearing if every provider fails.
- `watchdog.yml` (daily) runs `npm run health`: no new articles > 26 h, no AI summary > 36 h, no digest > 26 h, > 60 % failing sources or DB > 400 MB → opens/updates a GitHub issue labelled `watchdog` (GitHub emails the owner) and closes it when healthy again.

## 8c. Repository security
- `main` is protected by a ruleset (set in the GitHub UI): changes land only through a PR with the `check` job green; no force push or deletion. Dependabot PRs follow the same path.
- Workflows: top-level `permissions: contents: read` (raise per workflow only where needed: keepalive `actions: write`, watchdog `issues: write`), `actions/checkout` with `persist-credentials: false`, and every action pinned to a commit SHA with its version as a comment (Dependabot `github-actions` updates both). Add new actions the same way.
- `.github/dependabot.yml`: weekly, minor/patch grouped, 7-day cooldown on new releases. `ci.yml` runs `dependency-review` on PRs (fails on high-severity advisories).
  Held back on purpose: `@types/node` majors (follow the Node 24 runtime; Vercel offers only 22.x/24.x, Node 26 is not LTS yet) and `typescript` >= 6.1 (we run TS 6.0.x, the last version typescript-eslint supports: peer `>=4.8.4 <6.1.0`; it refuses TS 7). Check `npm view typescript-eslint peerDependencies` and Vercel's Node versions page before lifting either. `package.json` `overrides` pins `postcss-selector-parser` ^7.1.6 under `@tailwindcss/typography` (GHSA-rj75-hqrm-r3gf); the built `.prose` CSS was identical. A second override moves drizzle-kit's `@esbuild-kit/core-utils` to esbuild ^0.25.12 (GHSA-67mh-4wv8-2f99); `drizzle-kit generate` still works. A third pins `zod` ^4.6.7 under `@vercel/cli-config` (pulled in by `@vercel/functions` → `@vercel/oidc`; GHSA-mrhx-c7xc-m3w5, it shipped zod 4.1.11). Drop it once `@vercel/cli-config` upgrades. No `labels:` in dependabot.yml: a configured label must already exist in the repo, otherwise Dependabot comments an error on every PR.
- `docs/ARCHITECTURE.md` is the public technical write-up (English, mermaid diagrams). Update it when a pipeline, table or algorithm changes.
